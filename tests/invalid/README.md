Markup that must fail `block-runner validate --strict`. `npm run check` asserts it does, so a validator that has stopped rejecting anything turns the check red.

`design-broken-ref.md` is a DESIGN.md whose component points at a colour token that does not exist. `npm run check` asserts `@google/design.md lint` rejects it with a `broken-ref` error, so the DESIGN.md gate is shown to bite too.

`design-low-contrast.md` is a DESIGN.md the linter itself passes: no errors, exit 0, and one warning, a component with text under 4.5:1 against its background. `npm run check` asserts its DESIGN.md gate rejects it anyway, so the rule that fails the gate on any warning cannot be loosened to the linter's exit code without turning the check red.

`presets/` holds markup the presets gate must refuse, one file per rule: `colour.html`, `font-size.html`, `font-family.html`, `radius.html`, `shadow.html`, `spacing.html` and `html.html`. Each top-level block in a file breaks that file's rule in its own way and breaks no other rule. `npm run check` asserts the gate refuses every one of those blocks for its file's rule, so a rule that stops biting on any one case turns the check red. The files are assembled with Block Runner and `block-runner validate --strict` passes them, so only the presets gate refuses them. The one exception is the stray HTML at the end of `html.html`, which `--strict` warns on as well. They sit in a subfolder so the `tests/invalid/*.html` glob that `block-runner validate` must reject does not reach them.

`recipes/` holds page recipes the `rhythm` gate must refuse, one file per rule: `adjacent-accent.json`, the home page with its reviews turned accent beside the accent CTA band, so two accent sections meet, and `unknown-layout.json`, the contact page with its hero in a `banner` layout no hero intent carries, so the section names no pattern. Each breaks its rule once and no other rule, and `npm run check` asserts the gate refuses each for its own rule alone. Copying `adjacent-accent.json` into `recipes/` turns `npm run check` red.

`blocks/unknown-block.html` holds the pack's icon block and a block no plugin registers, `example/not-registered`. `npm run check` validates it with the same site context it gives the patterns, which lists the pack's own blocks, and asserts it fails on the unknown block alone: one `unregistered-block` warning, for `example/not-registered`, while the icon reads as registered on the target. So the context is shown to know the pack's blocks and no others. It sits in a subfolder so the `tests/invalid/*.html` glob does not reach it.

`no-tests.mjs` is a test file with no tests in it, which `node --test` reports as one passing test. `npm run check` runs it through the guard it puts on the known-answer tests, at the fold test's floor of 12 cases, and asserts the guard refuses it, so a known-answer test that lost its cases turns the check red.

`quick-card-500.md` is a copy of the entry skill, the quick card, less its release marker, padded to exactly 500 words as `wc -w` counts them. `npm run check` counts the real card and fails at 500 words or more, and asserts the same rule refuses this copy, so a budget loosened to 500 or more turns the check red. The real card changes; this copy only has to stay at 500.
